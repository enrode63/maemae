# Local demo runtime

This service is a deterministic simulation only. It contains no exchange, broker,
LLM, credential, real-money, deposit, or withdrawal integration. The server CLI
accepts only loopback bind targets.

Run from `backend` with Python 3.10+:

```powershell
$env:PYTHONPATH = "src"
python -m local_runtime --host 127.0.0.1 --port 8765 --state-dir local-state --interval-seconds 1
```

The host, port, state directory, and interval can be supplied as environment defaults.
Explicit CLI arguments take precedence for those four settings. CORS additions are
environment-only:

```powershell
$env:PYTHONPATH = "src"
$env:LOCAL_RUNTIME_HOST = "127.0.0.1"       # localhost or 127.0.0.1 only
$env:LOCAL_RUNTIME_PORT = "8765"            # 1..65535
$env:LOCAL_RUNTIME_STATE_DIR = "D:\demo-state"
$env:LOCAL_RUNTIME_INTERVAL_SECONDS = "1"
$env:LOCAL_RUNTIME_ALLOWED_ORIGINS = "https://my-ui.vercel.app"
python -m local_runtime
```

`LOCAL_RUNTIME_ALLOWED_ORIGINS` is a comma-separated list of exact `http://` or
`https://` origins. An origin is scheme + host + optional port, with no path. Wildcards,
userinfo, query strings, and fragments are rejected. The four built-in development origins
(`localhost` and `127.0.0.1`, with no port or port 3000) remain available. No origin is
inferred from a request. The bind host cannot be widened by either CLI or environment.

`--interval-seconds 60` gives a one-minute cycle; fractional values are useful in
tests. State and audit events are appended beneath `local-state`. A restart never
automatically resumes the worker.

Endpoints:

- `GET /health`, `GET /runtime/status`, `GET /results`, `GET /events`
- `POST /chat/conversations`
- `POST /chat/send`
- `POST /proposals/approve`, `POST /proposals/reject` (requires `actor_role: "PM"`)
- `POST /runtime/start`, `POST /runtime/pause`, `POST /runtime/stop`

POST bodies are JSON. Runtime controls require a unique `request_id`. Chat routes
follow `CHAT_API.md`.

For both chat routes, optional conversation context consists of `role`, `team`, and
`metadata`. Allowed roles remain `PM`, `Bull`, `Bear`, `Risk`, and `Research`; metadata
supports non-empty string fields `channel` and `team_label`. For example:

```json
{"conversation_id":"web-demo","role":"Research","team":"macro","metadata":{"channel":"fund-room","team_label":"Macro Team"}}
```

The existing `POST /chat/conversations` body containing only `conversation_id` remains
valid. `POST /chat/send` continues to require `conversation_id`, `request_id`, and
`content`; `content` is the canonical message body, and `message`, `text`, or `prompt` are
not aliases. Responses echo the effective context, which is also retained in audit events.

## Frontend contract

Set the frontend's API base URL to the operator-provided runtime URL, without a trailing
slash. A Vercel page origin must also appear exactly in
`LOCAL_RUNTIME_ALLOWED_ORIGINS`. A hosted browser cannot reach another machine's
`127.0.0.1`; exposing or deploying this backend is intentionally outside this project.
There is no authentication layer, so do not publish it to the internet.

All successful responses below are JSON with HTTP 200. Errors use
`{"error":"<type>","message":"<detail>"}` (400) or `{"error":"not_found"}` (404).

```http
GET /health

{"ok":true,"scope":"localhost-demo-only"}
```

```http
POST /chat/conversations
Content-Type: application/json

{"conversation_id":"web-demo"}
```

Response: `{"conversation_id":"web-demo"}`.

```http
POST /chat/send
Content-Type: application/json

{"conversation_id":"web-demo","request_id":"web-001","content":"시장 상태를 검토해줘"}
```

The chat response contains `conversation_id`, `request_id`, a `messages` array (User,
PM, Bull, Bear, Risk, and Research replies), and a `proposals` array. IDs generated by the
service are opaque. Send `proposal_kind` as `strategy` or `code` only when a pending
proposal is wanted; it is never applied without a separate PM approval.

```http
GET /runtime/status

{"config":{"interval_seconds":1.0,"quantity":"1","seed":7,"start_price":"100","symbol":"DEMO"},"error":null,"mode":"simulation","status":"idle","tick_sequence":0}
```

```http
GET /results

{"cash":"100000.00000000","events":[],"mode":"simulation","positions":[],"run_id":"<opaque>","runtime":{"config":{"interval_seconds":1.0,"quantity":"1","seed":7,"start_price":"100","symbol":"DEMO"},"error":null,"mode":"simulation","status":"idle","tick_sequence":0},"total_pnl":"0.00000000"}
```

The initial `status` is `idle`; start, pause, and stop use their documented POST routes.
Money and quantities are decimal strings, and clients must not treat `run_id` or generated
message/proposal IDs as stable values.

Test everything:

```powershell
$env:PYTHONPATH = "src"
python -m unittest discover -s tests -v
python -m compileall -q src tests
```
